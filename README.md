### Manuscript

Manuscript is a local-first writing assistant being developed for Windows and Android.

The Windows work emphasizes:

- On-device handling of speech, writing, and user content
- Local AI integration
- Encrypted local data using SQLCipher
- Windows user-bound key protection using DPAPI
- Loopback-only local model communication
- Guarded exports and path boundaries
- Server-verified subscription and entitlement architecture

The Android work emphasizes:

- Writing assistance in normal editable text fields across applications
- An accessibility-service trigger beside the active field
- A keyboard-sized inline review experience
- Swipeable correction cards and focused explanations
- Visible removals, insertions, and replacements
- Accept, dismiss, and tone-adjustment controls
- Compatibility with Android's `PROCESS_TEXT` flow
- System-keyboard voice typing instead of app-owned dictation

**Status:** Android builds have passed unit, lint, release-bundle, and emulator/Chrome text-field validation and have been distributed through private Google Play Internal testing. Broad physical-device, manufacturer, and Chromebook compatibility remains separate work. The Windows sales and subscription system has local implementation evidence but is not represented here as publicly deployed or sale-ready.

### DreamSync

DreamSync is a phone and Wear OS research prototype for studying wearable-assisted sleep-cue workflows.

The prototype includes:

- Coordinated phone and watch applications
- Wear OS and Android Data Layer messaging
- Probable sleep-state control logic
- Short pink-noise cue pairs
- Arousal backoff and cue limits
- Local CSV research logging
- Sensor-source and callback diagnostics
- Coordinated private Google Play Internal releases

**Research boundary:** DreamSync does not perform EEG or clinical AASM sleep staging. Its wearable estimates are probable control states. It does not claim clinical outcomes, guaranteed lucid dreams, increased deep-sleep minutes, immunity benefits, or EEG phase locking.

**Status:** Phone and Wear releases have been made available to private internal testers. Samsung sensor integration has connected and enumerated trackers, but live sensor delivery remains under investigation because policy errors and zero-callback conditions must be resolved before stronger sensor claims can be made.

### Chrome Reader

Chrome Reader is a Manifest V3 browser extension focused on readable web content, speech controls, and useful YouTube research packages.

Work includes:

- Browser text reading with Web Speech APIs
- Google and Windows Natural voice handling
- Clear recovery guidance when preferred voices are unavailable
- A single-action YouTube package workflow
- Structured metadata, description, link, and thumbnail output
- Transcript and subtitle recovery
- SRT, VTT, and plain-text transcript output
- Predictable download folders for creator research

**Status:** Voice handling and transcript/subtitle recovery have focused validation. YouTube packaging works within Chrome's download security boundaries, with some source-dependent behavior still requiring careful handling.

## How I Work

- **Evidence first:** I separate implemented features from directly verified behavior.
- **Privacy first:** Sensitive writing, speech, and personal content should stay local when the product allows it.
- **Security in the architecture:** Authentication, webhook verification, licensing, storage, and access controls belong in the design—not as late add-ons.
- **Accessible interaction:** Tools should work where people already type, read, create, and communicate.
- **Complete workflows:** A feature is more useful when packaging, recovery, errors, and real user paths also work.
- **Honest release status:** Local builds, private internal releases, live deployments, and public production releases are different kinds of evidence.
- **Resumable systems:** Expensive generated assets and completed work should survive crashes, limits, and interrupted sessions.
